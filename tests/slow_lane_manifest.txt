# TensorFEM slow-test registry -- the data behind the `slow` marker.
#
# Consumed by tests/conftest.py: every node id listed here is marked
# `pytest.mark.slow` at collection time, and the fast lane (`pytest --fast`,
# == `pytest -m "not slow"`) deselects exactly this set.  Nothing else in the
# suite is affected: the lanes change *which* tests run, never what they
# assert (see docs/test-lanes.md).
#
# Entry format: node id relative to the repository root, without a
# parametrisation suffix (`...::test_x` marks every parameter of test_x).
# Keep it sorted; the audit refreshes it from measurement:
#
#   pytest -q --junitxml=artifacts/junit.xml            # full lane, once
#   python scripts/slow_lane_audit.py --junitxml artifacts/junit.xml \
#       --threshold 5 --check                            # drift gate
#
# Registration policy (two independent reasons to be here):
#   1. measured cost >= 5 s per case on the reference machine (below), or
#   2. heavyweight by construction -- an opt-in qualification study that is
#      minute-scale whenever it actually runs.
# The measurement is a floor, not a ceiling: the loong64 CI node is slower than
# the x86 reference, so a case measured just under the cut-off may still belong
# here.  Adding an entry is cheap and reviewable; a *new* heavy test that is not
# registered is the drift that `--check` catches.
#
# Generated from a full-lane run: 118 entries at measurement time
# (114 measured >= 5 s, 4 registered by policy).  The test_verification_ladder
# entries appended at the end were measured at 27 s / 13 s / 10 s, plus one
# 8x8 plate eigen-solve case (3.6 s on the x86 reference, slower on loong64)
# registered by policy.
