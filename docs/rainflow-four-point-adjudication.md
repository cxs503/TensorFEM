## ① 案例介绍

`rainflow_cycles` 是 TensorFEM 全部疲劳数字的最前端（热点谱 Miner 损伤、焊缝筛选、
冰激振动的循环计数）。输入是应力时序，输出 `(range, mean, count=1.0|0.5)`。
2026-11-08 的审计（`docs/rainflow-counting-defect.md`）提出三条要求：结构化锚点
（等幅块 n 个 full、嵌套 `{1,1,2,2,3,3}`、三角 1 个 full、两级块 2×5+2×20）、窄带
随机谱 Rayleigh 损伤 <3%、正弦 40 周期 = 40 等效循环；并给出「嵌套记录损伤 234 vs
72，偏差 +225%」的量化结论。该件的修复尝试被自己的判据否决，缺陷留在 main 上，
两个 `xfail(strict=True)` 作为绊线。

本单要裁决的正是这个卡住的锚点：**哪一部分是计数器的缺陷，哪一部分是判据本身写错了。**

## ② 怎么做的（方法与工具链）

1. 只读两条历史上被尝试过的路线，并用一次**判别性实验**（`/tmp` 探针）量化其后果：
   - 现有实现（三点栈 + `len(stack)==3` 特判 → 全部记 0.5）；
   - 「只删特判」的三点规则修复（等幅/三角立刻正确）；
   - 教科书四点规则（`|S3-S2| ≤ |S2-S1|` 且 `|S3-S2| ≤ |S4-S3|` 才闭内环）。
2. 判据：弧守恒 `Σ count·range = ½ Σ|Δs|`（对 80–120 条随机闭合记录逐条核对）、
   结构化锚点、等效循环数、损伤 `Σ count·range^m`（m=3，无平均应力项 → 与 mean 无关）。
3. 交付：把四点规则写进 `rainflow_cycles`（栈式实现，闭合记录残留的最外区间配对
   成 1 个 full cycle），并新增**结构独立**的复核器 `four_point_reference`
   （重复扫描版，不共享栈代码）与「水平穿越（插值闭合）」分解器，三者同表对比。

## ⑤ 注意点（踩坑/局限/适用范围）

- **只删 `len(stack)==3` 特判不是修复**：三点规则在扩张锯齿上闭出 range 1/3/5 三个
  「环」，随后丢掉 1.5 个单位弧长——80 条随机闭合记录里 **71 条**违反弧守恒。
  这解释了 2026-11-08 那次「保留插值层级」的修复为什么被自己的判据否决：
  缺的不是插值，而是**第四点**（必须同时看 `S2-S1` 与 `S4-S3` 两侧）。
- 闭合记录残留：外侧首尾区间（range 相等时）配成 1 个 full cycle，其余残留区间按
  半循环计。这不改变损伤（`0.5+0.5` 与 `1.0` 同权），只改变结构标签；正弦这种
  未闭合记录仍以半循环收尾（39 full + 3 half = 40.5 等效，±5 % 内）。
- `mean_pa` 在合并的闭合环上取 `(stack[0]+stack[1])/2`（= 峰谷中点），平均值修正
  公式在此约定下与「两个半循环」一致。
- 下游影响：Miner 损伤对 count 是线性的，故等幅/两级块/正弦类谱的**损伤不变**；
  变化只出现在循环结构（full/half 标签）与随后的**平均应力修正**（该修正按 count
  加权时，标注为 1 个 full 与 2 个 half 等价）。结构化结论无需撤回，反而现在有了
  正确的循环集合。
- 局限：未对照 ASTM E1049 原图逐例核对「闭记录残留按半循环计」的约定，仍标
  WITHHELD；`weld_fatigue_ice` / 冰激振动链未见回归红灯，但只跑了单文件 pytest，
  全仓疲劳面未做端到端复跑。
