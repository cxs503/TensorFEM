# CASE-LBM-THUEREY-VOF-MASS-EXCHANGE — Thürey free-surface VOF mass exchange, independently verified

Anchor: `XVAL-LBM-THUEREY-VOF-MASS-EXCHANGE` ("Maarten-vd-Sande/lbm 的 thuerey-vof-mass-exchange 做法").
Acceptance: agreement with analytic / literature references within 15 %.
Module: `src/tensorfem/lbm_free_surface_thuerey.py`; tests: `tests/test_lbm_free_surface_thuerey.py`;
raw numbers: `artifacts/xval_thuerey_vof_measurements.json` (all figures/tables below are generated by
`scripts/xval_thuerey_vof_measurements.py`, nothing hand-copied).

## 1. What is being verified

The Thürey / Körner free-surface LBM splits the domain into GAS / INTERFACE / FLUID / SOLID cells and
tracks liquid mass `m` on the interface cells only.  After streaming, an **exchange** step (Thürey & Rüde
2009) redistributes the mass of cells that overflow (`m > ρ` → promoted to FLUID) or run dry (`m < 0` →
demoted to GAS).  Without that step a solver simply clips `m` into `[0, ρ]` (the widespread shortcut) and
liquid disappears at every conversion.  The claim under test is the conservation claim of the exchange,
not the existence of the code: *mass is moved between cells, never created or destroyed.*

Flux implemented (post-collision populations `f*`, `e_i` the lattice direction, `opp` its opposite):

| neighbour | flux into interface cell `x` |
|---|---|
| FLUID | `f*_opp(x+e_i) − f*_i(x)` |
| INTERFACE | `½[(f*_opp(x+e_i) − f*_i(x)) + (f*_i(x+e_i) − f*_opp(x))]` |
| GAS / SOLID | 0 |

The interface/interface term changes sign for the mirrored pair, so `dm_i(x) + dm_opp(x+e_i) = 0`.

there is no free-surface reconstruction activity.

## 3. Why the physical checks fail (diagnosis, not excuse)

* The gas-side reconstruction `f_i = f_i^eq(ρ_atm,u) + f_opp^eq(ρ_atm,u) − f_opp` is **not mass-neutral**.
  Each step it injects/removes populations at the surface, and the injected mass is not booked into `m`.
  In a flowing dam break the number of surface cells grows (175 → 360 over 2000 steps), so this channel
  dominates: the liquid volume defined as `Σ_FLUID ρ + Σ_INTERFACE m` drops by ~4.5 % per 1200 steps and
  ~17 % per 2000 steps.
* With gravity the interface cells see the hydrostatic density difference `w_i (ρ_below − ρ_above)` as a
  *real* flux term, so a resting column slowly pumps liquid into the interior; the pressure profile never
  settles and no `ρ(y) = 1 + 3g(h−y)` develops (measured slope has the wrong sign).
* The dam-break front is then ~4x too slow (front speed 0.0096 vs Ritter 0.04 in lattice units), i.e. the
  missing liquid is exactly what the front needs.

A deliberately exactly-conservative alternative was implemented and **rejected**: pin every FLUID cell at
`m = 1` each step (VOF capacity per cell) and push the deviation into neighbouring interface capacity.
It conserves volume to machine precision (drift 0.0 over 2000 steps) but destroys the pressure support —
the resting column free-falls (`u_y ≈ g t`) and a dam break never collapses (front stuck at the dam).
That negative result is recorded here so the next worker does not repeat it.
