## 3. Findings (severity-ranked)

**F1 — medium (evidence labelling, not physics).** `evidence.json:external_anchor.kelvin_patch_moment`
names `tensorfem.levelset.plate_crack.patch_max_moment` as the "exact Kelvin-function centre
moment"; that function lives in the *same* packet and its own docstring says the `(1+ν)/2`
prefactor was "confirmed by the finite-element moment field", so as shipped the benchmark
compares two code paths with shared derivation lineage. *Status: neutralised by this audit* —
the Hankel re-derivation is fully independent and agrees to 2e-6 relative. Repair: relabel as
"analytic reference (Kelvin/Hetényi), independently re-derived — see
`artifacts/audit_m14883/`".

**F2 — medium (provenance).** `evidence.json` records `git_commit = e5185c94` (the *base*
commit) and `dirty = true`; the delivered commit is `88415e77`. The artifact is therefore not
bound to the sha it ships with. The script hash is correct (`d9f61087…` matches the committed
benchmark), and reproduction here is clean, so this is bookkeeping, not evidence damage. Repair:
write `git rev-parse HEAD` + `git status --porcelain` into the evidence at generation time and
regenerate after committing.

**F3 — medium (maturity cap, no production caller).** Nothing consumes
`ice_plate_flexural_limit` except its own benchmark and tests; the only "integration" is one-way
reuse of the GAP-FEM-WINKLER kernel. Per the platform's own precedent (verdicts on m14685
"`L3_blocked: no integration callers`" and m14980 "`L3_refused: not passed by any production
caller`"), zero production callers caps the reported level at **L2**. Concrete remediation: wire
`first_crack_load` into the ice-load workflow (TensorPhysics `ice_sheet/design_laws.py:225`
currently duplicates the same `P_c = M_f / m_hat` physics with a *different* `m_hat` source —
reconciling the two would be an immediate cross-check of both, and is the cheapest route to L3).

**F4 — low (criterion ③ only partially substantiated).** The limit-load comparison stops at
a/l = 2, while the mode map runs to a/l = 8; at a/l ≥ 3 the critical point migrates to
r/a ≈ 0.44–0.83 where no analytic reference is used. "Failure location and mode are correct"
therefore rests on internal mesh stability (80 vs 120 cells) only — reasonable, but it is
consistency evidence, not validation. Repair: add a large-patch reference (e.g. compare the
circumferential-mode moment against the thick-plate/point-loaded limit, or against an
independent 2-D solver).

**F5 — low (untested surface).** The reused kernel's own suite (`tests/test_foundation_plate_bending.py`
et al.) was not run in the mission ("tool timeout" in the mission result) nor here (single command
cap 120 s in this container). Risk is low — the diff adds files only — but the claim "no
regression surface" is inferred, not demonstrated. Repair: run the neighbour suite on the cluster
queue once and cite the job id.

## 4. Checks not run (unknown, not "passed")

## 6. Disposition

**Approve with notes; reported maturity level 2.** The numerical layer is sound, reproducible and
independently validated (benchmark evidence is L4-grade: complete case + convergence + error
analysis + reproducible against an analytic reference); the single substantive gap is L3 —
no production/workflow caller, and a duplicate implementation in TensorPhysics. Recommended
remediation, in order: (1) relabel `external_anchor` and bind the evidence to the delivered
commit (F1, F2 — minutes); (2) wire the module into the ice-load path or reconcile it with
TensorPhysics `ice_sheet` (F3 — the only blocker to L3); (3) extend the anchor past a/l = 2 (F4).
