# FEM_VERIFY — analytic verification of the three classical structural models

Status: **passing** (see Table 4 below; tables are regenerated by
`benchmarks/euler_bernoulli/run.py`, prose is hand-written).
Artefacts: `benchmarks/euler_bernoulli/{run.py,validate.py,results.json}`,
figures in `docs/assets/fem_verify/`.

This page records one benchmark per classical structural model that a hull or
offshore structure analysis leans on — the **Euler-Bernoulli beam**, the
**thin plate**, and the **elastic half-space** — each graded against a
closed-form reference, each with a refinement ladder so that *the discretisation
error is measured, not asserted*. All reference values are computed inside
`run.py` (Navier series, Boussinesq influence integral) instead of being typed in
from a table, so the numbers cannot drift out of sync with the code.

## 1. Case 1 — Euler-Bernoulli cantilever, `L/h = 100`

### 1.1 Geometry and parameters

| quantity | symbol | value |
|---|---|---|
| length | `L` | 1.0 m |
| cross-section | `b × h` | 10 mm × 10 mm |
| slenderness | `L/h` | 100 |
| Young's modulus | `E` | 200 GPa |
| Poisson's ratio | `ν` | 0.3 |
| tip point load | `P` | 5 N (transverse) |
| reference | `δ = PL³/(3EI)` | `I = bh³/12` |

### 1.2 Method

Two discretisations of the *same member* are run over a ladder:

* **`frame2d` cubic-Hermite Euler-Bernoulli elements** (2 dof per node plus
  axial). For an end-loaded cantilever the cubic Hermite field contains the
  exact solution, so every level reproduces the analytic tip deflection up to
  round-off — this is a check of assembly, transformation and the constraint
  elimination, not of the theory.
* **HEX20 quadratic 3-D solid** (`structured_hex20_mesh`, 60-dof elements,
  root face fully clamped, resultant of `P` spread over the loaded tip face).
  This model is *not* allowed to assume beam kinematics, so it must converge to
  `PL³/(3EI)` as the mesh is refined: it is the level that actually qualifies
  the 3 % criterion. Levels: 10 and 20 quadratic elements along the axis at two
  cross-section cells, plus a 20-element level with four cells across the
  section.

### 1.3 Results

See **Table 1** in §4.

### 1.4 Notes

* The frame ladder sits at 1e-13 — correct, and deliberately reported anyway so
  that the table shows *which* discretisation carries the engineering risk.
* The residual solid-model error is the clamped-root artefact: a fully clamped
  cross-section suppresses Poisson contraction and warping, so the root region
  is locally stiffer than beam theory. Its relative weight falls with `h/L`,
  which is exactly what the 10 → 20 axial ladder shows; the cross-section
  refinement (2 → 4 cells) has little left to contribute, i.e. the remaining
  error is *modelling* (3-D root restraint), not resolution.
* Transverse shear is deliberately absent from the reference: for `L/h = 100`
  the Timoshenko correction is `≈3(1+ν)h²/(5L²) ≈ 8e-5` of the bending value,
  below the reporting resolution of the table.

## 2. Case 2 — thin simply-supported square plate under uniform pressure

### 2.1 Geometry and parameters

| quantity | symbol | value |
|---|---|---|
| side | `a` | 1.0 m |
| thickness | `t` | 10 mm (`a/t = 100`) |
| Young's modulus | `E` | 200 GPa |
| Poisson's ratio | `ν` | 0.3 |
| uniform pressure | `q` | 1 kPa |
| boundary | — | hard simple support (`w = 0`, tangential rotation free-to-zero) |

### 2.2 Method

Q4 Mindlin plate elements (`q4_mindlin_stiffness`) with selective reduced
integration of the transverse shear block (`shear_treatment="sri"`, 1-point
shear / 2×2 bending), uniformly distributed pressure load, w = 0 and in-plane
rotation = 0 on the four edges. Ladder: `n = 8, 16, 24` elements per side.

Reference: the **Navier double series** for the SS square plate evaluated in
`plate_navier_series` (399 × 399 odd terms), plus the textbook coefficient
`0.00406` (Timoshenko & Woinowsky-Krieger, *Theory of Plates and Shells*) as an
independent anchor. The series and the table value agree to `2e-3 %`, so the
3-digit table coefficient is not the limiting factor.

An independent shear treatment (`shear_treatment="mitc"`, assumed natural
transverse shear) is solved on the coarsest level; a ladder that only works for
one shear trick would show up as a disagreement between the two.

### 2.3 Results

See **Table 2** in §4. Centre deflection coefficient
converges onto `0.00406...` from below; the coarse grid is stiff, as expected for
a displacement-based Mindlin element in the thin limit.

### 2.4 Notes

* At `a/t = 100` the plate is well inside the Kirchhoff regime: the Mindlin
  transverse-shear contribution is `O((t/a)²)` and therefore invisible at this
  precision. Using the Kirchhoff series as the reference is legitimate here —
  it would *not* be for the `a/t = 10` thick-plate benchmarks
  (`benchmarks/plate_uniform_load_evidence.json`).
* The hard simple support (`w = 0` and tangential rotation = 0) is the
  admissible boundary condition of the Mindlin theory; the Kirchhoff "soft"
  support differs only in an `O(t)` boundary layer, which is why the two
  references bracket the same number.
* The uniform load is integrated with 2×2 Gauss points per element; for the Q4
  geometry this is exact up to the Jacobian.

## 3. Case 3 — Boussinesq half-space settlement (3-D elasticity)

### 3.1 Problem and parameters

| quantity | symbol | value |
|---|---|---|
| half-space | `E`, `ν` | 1 MPa, 0.3 (soil-like, chosen so the displacement is O(mm)) |
| loaded patch | `2a × 2a`, `a` = 1 m | uniform pressure 1 kPa |
| model | quarter box `[0,L]×[0,L]×[0,D]` | symmetry planes `x = 0`, `y = 0`; rollers on `x = L`, `y = L`; bottom fixed in `u_z` |
| reference | Boussinesq (1885) / Love (1929) | `w(x) = (p(1-ν²)/(πE)) ∫_A dA/|x-ξ|` |

The reference integral is closed for the rectangle (`settlement` in
`tensorfem.elastic_halfspace`, Newmark corner inclusion-exclusion), and the
module's test suite grades that closed form against a composite Gauss quadrature
of the point-load kernel — so the reference is not self-certified.

### 3.2 Method

Graded HEX8 quarter model: `n_fine` uniform cells of size `a/n_fine` over the
loaded patch, then geometrically growing cells out to `lateral·a` and down to
`depth·a`. Ladder (Table 3): levels 1 → 2 refine the mesh at a fixed 20a box
(discretisation), levels 2 → 3 → 4 grow the box to 30a and 40a (truncation).
The linear system is solved with the SuperLU adapter
(`tensorfem.sparse_direct.factorize_sparse`); the coarsest level is re-solved with
the library's unpreconditioned CG path (`solve_halfspace_patch`) as an
equivalence check (`halfspace.solver_cross_check` in `results.json`, agreement at
the 1e-12 level).

### 3.3 Results

**Table 3** in §4 lists centre settlement against the closed form, the corner value (a
second, more truncation-sensitive point) and the reaction balance. The error is
**negative** — the FE settlement is *smaller* than the Boussinesq value — because
rollers on the outer vertical faces plus a fixed bottom make the truncated box
stiffer than the infinite half-space: confinement suppresses the far field that
carries a large share of the settlement of a `1/r` kernel.

The trend with the truncation radius is the physically honest reading of this
table: 20a → 30a → 40a buys about a percentage point per step and does **not**
converge quickly. That is a property of Boussinesq truncation, not of the
element: refining the mesh at a fixed box (levels 1 → 2) moves the answer by a
comparable amount. Both knobs are therefore tabulated instead of hiding one
behind the other.

### 3.4 Notes / limitations

* **The residual error is truncation, and no residual or reaction check can see
  it.** In every level the reaction balance is at the 1e-11…1e-16 level while the
  centre settlement is off by percent — this is exactly the failure mode the
  module was built to expose, and the reason a *closed-body* benchmark would
  have declared this model correct.
* The remaining 3 % at the 40a box is *not* removed by relaxing anything: it is
  reported, and the acceptance limit (5 %) is applied to the finest level
  unchanged.
* Surface settlement away from the load axis (Figure
  `docs/assets/fem_verify/halfspace_settlement.png`, left panel) shows that the
  *shape* of the FE field follows the closed form closely even where the
  absolute value is a couple of percent low — the error is close to a uniform
  scale factor, i.e. it comes from the far field, not from the loaded patch.
* Deep layers are graded geometrically; the bottom boundary is quite coarse and
  the `u_z = 0` plane is a modelling choice, not a physical condition. A
  free-bottom alternative would be *less* stiff only if the box were also deeper;
  we did not implement it (see "Not done" below).
* Runtime: 4 levels ≈ 4 minutes single-threaded (the SuperLU factorisation of
  the 25k free-dof level dominates). A torch-only installation without SciPy
  falls back to the library CG, which converges to the same answer but is ~10×
  slower at the same mesh.

## 5. Reproduce

```bash
OMP_NUM_THREADS=8 PYTHONPATH=src python benchmarks/euler_bernoulli/run.py      # ~4 min, rewrites results.json + tables + figures
PYTHONPATH=src python benchmarks/euler_bernoulli/validate.py                   # machine gate, exit 0/1
OMP_NUM_THREADS=8 PYTHONPATH=src python benchmarks/euler_bernoulli/run.py --skip-halfspace   # beam + plate only, ~20 s
```

## 6. Not done / out of scope

* No thick-plate (`a/t = 10`) case here — covered by
  `benchmarks/plate_uniform_load_evidence.json` (Mindlin vs 3-D reference).
* Cantilever with an end *moment* and cantilever free vibration are covered
  elsewhere (`benchmarks/beam_dynamics_validation.md`,
  `benchmarks/timoshenko_beam_modal_reference.json`); this page only grades the
  static tip-deflection criterion requested for the benchmark contract.
* Half-space with a *free* bottom face and an absorbing far field (a truncation
  error below 1 % would need it) is not implemented — the 40a box with rollers
  is where the ladder stops.
* No Python-level unit test re-runs the ladders (they cost minutes); CI calls
  `validate.py` against the committed `results.json` instead, and the analytic
  layers of `tensorfem.elastic_halfspace` are covered by
  `tests/test_elastic_halfspace.py`.
