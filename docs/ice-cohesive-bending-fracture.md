# Cohesive-interface mode-I fracture of an ice beam in three-point bending

**Module** `src/tensorfem/cohesive_bending.py` ·
**Benchmark** `benchmarks/ice_cohesive_bending_fracture.py` ·
**Tests** `tests/test_cohesive_bending.py` ·
**Artifacts** `artifacts/ice_cohesive_bend/` ·
**Date** 2026-11-10

## ① Scope and physics

The module adds a *zero-thickness cohesive interface element* path to TensorFEM
and uses it to simulate progressive mode-I fracture of a brittle plate/beam in
three-point bending: elastic response → damage initiation at the tensile face →
upward crack propagation along the symmetry plane → post-peak softening. The
interface plane is pre-meshed (standard cohesive-element practice); the crack
*front* is not prescribed — it emerges from the damage state, and for a
symmetric three-point bend the mode-I crack plane **is** the symmetry plane, so
the pre-meshed plane is exact rather than an assumption about the crack path.

| object | what it is |
|---|---|
| `BilinearCohesiveLaw` | irreversible bilinear mode-I traction–separation law; envelope area is `G_f` exactly (`0.5 σ_f δ_f`, `δ_f = 2G_f/σ_f`); compression keeps the undamaged stiffness; unloading is secant to the origin |
| `BilinearCohesiveLaw.from_material` | builds the penalty stiffness from the cohesive length `l_ch = E G_f/σ_f²`, `K = 50 E/l_ch`, so `δ_0/δ_f = 1 %`, independent of the mesh |
| `build_three_point_bend` | structured Q4 plane-stress mesh with a **duplicated node line** on the mid-span, pin/roller supports and a finite load patch on the top face (a patch removes the singular point-load field without changing the mid-span moment) |
| interface element (in `_assemble`) | two-node linear interface, 2-point Gauss, normal (`+x`) mode-I springs plus elastic tangential springs, **analytic consistent tangent** including the damage term |
| `solve_cmod_control` | Newton path follower driven by the crack-mouth opening; the load enters through a platen whose stroke is an unknown, so the load is the stroke reaction and the stroke may decrease post-peak |
| `solve_arclength` | spherical arc-length (Crisfield) follower for the same model, kept as the limit-point-capable alternative |
| `flexural_strength_load`, `timoshenko_midspan_deflection` | the analytical anchors |

## ② Case definition (ice, S/d = 4)

| parameter | value |
|---|---|
| Young's modulus `E` | 5.0 GPa |
| Poisson ratio `ν` | 0.30 |
| tensile strength `σ_f` | 1.5 MPa |
| fracture energy `G_f` | 1.0 J/m² |
| span `L` | 0.16 m (S/d = 4) |
| depth `d` | 0.04 m |
| thickness `b` | 0.04 m |
| cohesive length `l_ch = E G_f/σ_f²` | 2.22 mm (`l_ch/d = 0.055`) |
| damage / failure opening | `δ_0 = 1.33e-8 m`, `δ_f = 1.33e-6 m` |
| analytical flexural limit `P = 2 b d² σ_f/(3L)` | 400 N |

| dissipated fracture energy vs input `G_f` | < 3 % | +12.3 %, +22.2 % | **FAIL (honest)** |
| complete fracture (crack through the depth) | required | crack stopped at 5.0 mm of 40 mm (12.5 %) | **FAIL (honest)** |
| global work/energy balance | audit | residual ≈ −(1.0 … 1.2)e-3 J against 2.4e-4 J dissipated | **not closed** |

### Why the energy criterion fails (diagnosis, not excuse)

`G_f·b·a` with `a` = height of the *fully separated* interface is not the whole
dissipated energy: the partially damaged crack-tip element still stores part of
its envelope. The deficit is therefore bounded by one segment,
`|E_diss − G_f b a| ≤ G_f b h_seg`; with `h_seg/a = 0.33` (16×16) and 0.25
(24×24) the bound is 33 % / 25 % while the observed excesses are 12.3 % / 22.2 %,
i.e. **inside the discretisation bound** but far above the 3 % gate. Passing the
gate needs `h_seg ≲ 0.03 a`, which at the achieved crack length means
`ny ≳ 300` (≈10⁵ dof) *and*, more fundamentally, a path follower that reaches a
long crack (below).

### Why the crack stops

`E_diss` reaches only 2.4e-4 J = 15 % of the full mid-span section energy
`G_f b d = 1.6e-3 J`, so the simulated crack is short and the energy comparison
is dominated by the tip element. Both the CMOD and the arc-length followers hit
a *turning point* of the discrete cohesive model after 3–4 segments have failed:
the Newton corrections collapse, the step size decays geometrically to the
floor and the run ends. This is a solver limitation of this delivery, not a
statement about ice — physically the crack must keep growing, and the turning
point is caused by the abrupt failure of a single interface segment. Remedies
planned for a follow-up node: (i) viscous regularisation of the damage
evolution, (ii) damage (constitutive) arc-length with the maximum damage
increment as path parameter, (iii) a quasi-static staggered (secant) scheme.

### Global energy balance

The platen work `∫P dΔ` accumulated over the stick-slip steps does not close
`W_ext = U_elastic + W_diss` (residual ≈ −5× the dissipation). The two
independent dissipation measures (path integral vs envelope) *do* agree, so the
constitutive bookkeeping is self-consistent; the discrepancy is in the
external-work accumulation across snap-back steps. Reported as an open audit
item rather than hidden.

## ⑤ Notes, limitations, applicability

* Mode-I only: the tangential interface response is a linear penalty, so
  mixed-mode (shear-dominated) ice failure is out of scope.
* The crack path is confined to the pre-meshed plane. This is exact for the
  symmetric three-point bend; it is *not* a general crack-tracking capability.
* Small strain, rate-independent, isothermal. Ice is rate sensitive
  (ductile-to-brittle transition); the parameters represent a brittle,
  low-temperature, high-rate limit.
* The load is applied over a patch of `0.25 d`; a point load would put a
  singular field next to the crack mouth.
* `solve_arclength` traces the path up to the peak but stalls at the limit
  point in the current implementation; it is not the production path.
* Peak-load discretisation: the two meshes bracket the analytical value
  (−0.7 %, +4.5 %). The non-monotone trend comes from the discrete failure of
  the first segment and from the different states at which the solver stops, so
  the peak load carries a ±5 % discretisation band at this resolution.
