# `fem_shell4_formulation_matrix` certificate repair (mission m20935)

## 1. What was wrong

The anchor shipped a study (`study.py`) and a result dump, but **no
`gates_verified.json`**, so `tools/verified_anchor_audit.py` graded it
`uncertified / E_NO_GATES` and `benchmarks/verified/anchor_certificate_debt.json`
carried it as debt. Consequences:

* nothing in the test suite turned red if the numbers drifted — the historical
  ladder simply skipped an anchor without gates;
* the dump was named `results.json` while the auditor looks for `result.json`,
  so the anchor additionally reported `has_result = false`;
* the convergence-order helper returned the raw least-squares **slope** of
  `log|error|` vs `log(size)`, i.e. every convergent ladder was published with a
  *negative* "order" (membrane ladders printed `-1.998` for a genuine `p = 2`).

## 2. What this mission changed

| file | change |
|---|---|
| `study.py` | `observed_order` now returns `-d log|error| / d log(size)` (order `p`, positive when the error shrinks); dump renamed `results.json` → `result.json` |
| `make_gates.py` (**new**) | emits the certificate from a fresh run (`--fresh`) or from the committed dump; renders both figures straight into `docs/assets/` |
| `gates_verified.json` (**new**) | 17 gates, canonical `tensorfem.verified-gates.v1` envelope, 17 numeric criteria, 4 *negative controls* |
| `tests/test_shell4_formulation_matrix_certificate.py` (**new**) | pins the certificate: verdicts recompute, values track the dump, negative controls are one-sided, anchor certified and out of debt |
| `benchmarks/verified/anchor_certificates.json`, `anchor_certificate_debt.json`, `docs/verified-anchor-certificate-table.md` | regenerated by `tools/verified_anchor_audit.py --write` |

The accepted configurations (`+ MITC` transverse shear) reach **0.56 % / 0.99 %**
at `n = 24`, i.e. inside the 3 % band against the published value. The two SRI
configurations are **34–54 % wrong and diverge with refinement**
(`p = -0.32` for `shell4+sri`), exactly as the per-facet rank census predicts:
SRI leaves **2 spurious zero-energy modes per facet** and one of them survives
assembly (`null_dim = 8` instead of 7). This is now a *gated* statement
(`C.scordelis_lo.order_sri`, `C.scordelis_lo.sri_degradation`,
`A.sri_spurious_present`, `B.assembled_sri_spurious`) rather than prose: a future
genuine fix of SRI turns those four gates red and forces re-baselining.

and the anchor now says so in machine-checkable form.

## 6. Limitations

- The Scordelis-Lo target -0.3024 m is the published converged FE value of the benchmark (four significant digits), not a closed form; the accepted configurations converge to -0.3054 m, i.e. a ~1 % offset that mesh refinement cannot remove. The 3 % gate therefore measures 'inside the published reference band', not 'analytic exactness'.
- shell4_mitc + MITC stalls at 0.94 -> 0.99 % between n = 16 and 24 (order 1.49 by fit); the slight uptick is that model-vs-reference offset, so the ladder is graded by the smallest error reached, not by monotonicity.
- The negative-control gates (A.sri_spurious_present, B.assembled_sri_spurious, C.scordelis_lo.order_sri, C.scordelis_lo.sri_degradation) pass while SRI is defective. They are intentional: they make the known deficiency a checkable claim instead of prose. If SRI is ever fixed they turn red and this file must be re-baselined.
- The rank census is a linear-algebra statement about the element matrices at one facet (Y = 200 GPa, nu = 0.3, t = 10 mm). It does not by itself prove mesh-level stability for non-flat (warped) facets or for nonlinear kinematics.
- Flat-facet Shell4 cannot represent a curved shell exactly: the membrane block's error is O(h^2) purely from chord-vs-arc geometry, which is why its order is 2 and not better.
- Every number is float64 torch on CPU; the machine-precision invariant gates are set at 1e-8..1e-10, four to seven decades above the observed 1e-12..1e-16 noise, so they detect a formulation error rather than a compiler difference.
